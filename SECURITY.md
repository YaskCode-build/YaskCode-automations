# Seguridad / Security

## Español

Edición 0.1.0 experimental: no hay una versión estable soportada. El código se distribuye con simulación activada. No publicar credenciales, contactos ni detalles explotables en issues, PR o Discussions.

Para un posible fallo, abrir la pestaña **Security → Advisories → Report a vulnerability**, si el botón está disponible. Ese mecanismo depende de que el reporte privado esté habilitado. Si no aparece, abrir únicamente un issue sin detalles técnicos sensibles solicitando que se habilite un canal privado; esperar a disponer de él antes de compartir evidencia. No se promete plazo de respuesta ni un canal privado no verificado.

Mantener secretos fuera de Git y usar cuentas de prueba. Si una credencial queda expuesta, revocarla o rotarla antes de limpiar archivos/historial: borrar un archivo no revoca acceso. Verificar las correcciones con datos sintéticos.

El repositorio no administra el activador ni el código de producción de la mantenedora.

## English

Edition 0.1.0 is experimental; no stable version is supported. Dry-run is enabled by default. Never publish credentials, contacts or exploitable details in issues, PRs or Discussions.

For a potential vulnerability, use **Security → Advisories → Report a vulnerability**, if available. This depends on private reporting being enabled. If unavailable, open only a non-sensitive issue asking maintainers to enable a private channel; wait for it before sharing evidence. No response deadline or unverified private channel is promised.

Keep secrets out of Git and use test accounts. Revoke/rotate exposed credentials before cleaning files/history; deleting a file does not revoke access. Verify fixes with synthetic data.

This repository does not manage the maintainer’s production source or trigger.
