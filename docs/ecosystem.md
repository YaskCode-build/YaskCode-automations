# Referentes, colaboración y visibilidad

[English](ecosystem.en.md)

Objetivo: que las personas puedan aprender con YaskCode, reutilizar sus automatizaciones y colaborar. La visibilidad se construye con ejemplos útiles, resultados comprobables y aportes a comunidades afines. Citar estos proyectos no implica colaboración, afiliación ni respaldo de sus autores.

## Cuatro referencias con funciones diferentes

| Repositorio | Qué aporta | Cómo usarlo en YaskCode | Oportunidad de colaboración |
| --- | --- | --- | --- |
| [googleworkspace/apps-script-samples](https://github.com/googleworkspace/apps-script-samples) | Ejemplos oficiales por servicio, soluciones y activadores; ejemplos de validación de .gs | Contrastar uso de APIs y elaborar prácticas con explicación propia | Corrección reproducible o mejora de documentación conforme a sus reglas |
| [labnol/code](https://github.com/labnol/code) | Catálogo de fragmentos y proyectos prácticos de Amit Agarwal / Digital Inspiration | Estudiar claridad de ejemplos y descubrir problemas aplicables a educación | Informar un fallo verificado o compartir una adaptación útil en un canal admitido |
| [labnol/apps-script-starter](https://github.com/labnol/apps-script-starter) | Entorno con Vite, Jest, ESLint, Prettier y clasp | Referencia para evolucionar herramientas; nuestra primera V4 sigue sin requerir esos paquetes | Mejora concreta de guía o ejemplo de pruebas, si coincide con el alcance del proyecto |
| [hubspotdev/crm-object-sync](https://github.com/hubspotdev/crm-object-sync) | Demo con OAuth, PostgreSQL, Prisma y sincronización por correo | Comparar persistencia y autenticación con nuestra variante Apps Script | Caso de prueba o mejora de documentación sobre un problema confirmado |

HubSpot ofrece aquí una demo con servidor y base de datos: no es una dependencia de V4 ni una solución sin servidor propio equivalente. Estos repositorios son referencias estudiadas; no hemos incorporado su código. Si se reutiliza después, revisar la licencia exacta del archivo y versión, conservar avisos y registrar la adaptación. No asumir que compartir lenguaje o plataforma concede permiso de copia.

## Qué hace y qué no hace una mención en GitHub

| Mecanismo | Efecto esperado |
| --- | --- |
| Enlace a repositorio en README | Referencia navegable; no es un aviso garantizado a sus autores |
| @usuario en issue, PR o Discussion | Puede generar notificación si la persona tiene acceso y según las condiciones de GitHub |
| @organización | No equivale a notificar a todos sus integrantes; los equipos usan mecanismos y permisos específicos |
| Mención en mensaje de commit | GitHub anunció en diciembre de 2025 que dejó de generar esas notificaciones |
| Star, fork o follow | Facilita guardar, reutilizar o seguir; no garantiza difusión, colaboración ni respuesta |
| PR externo | Propone un cambio real y revisable al proyecto, sujeto a sus reglas |

El repositorio actual es privado. Una persona externa no podrá leerlo solo porque aparezca mencionada. No usar menciones en un PR privado como mecanismo de presentación.

## Ruta de networking propuesta

1. Completar una primera entrega bilingüe con instrucciones, límites y evidencia honesta.
2. Publicar únicamente después de la revisión y confirmación de la mantenedora.
3. Revisar CONTRIBUTING, licencias y canales habilitados de cada proyecto externo.
4. Elegir un aporte pequeño que mejore ese proyecto: documentación, reproducción de un fallo o prueba. Verificar que no esté resuelto.
5. Preparar un PR o una participación útil en la categoría de Discussion adecuada, si existe y acepta mostrar proyectos. Usar inglés conciso y ofrecer documentación española como complemento.
6. Si es pertinente, enlazar el caso YaskCode como contexto de uso, no como condición ni único contenido del aporte.
7. Compartir el resultado en el campus, newsletter y redes de YaskCode. Referir la colaboración con exactitud: propuesta, aceptada o pendiente; nunca anunciar respaldo inexistente.

No se han enviado menciones, mensajes, issues o PR a estos cuatro proyectos. Las acciones externas requieren una instrucción concreta y seguir las reglas del proyecto receptor.

## Cómo multiplicar el aporte

- Guías en español e inglés con enlaces recíprocos y la misma versión técnica.
- Plantilla común: teoría, comparación, práctica, aplicación y resultados.
- Ejercicios para estudiantes que produzcan pruebas o documentación útiles.
- Casos replicados por otras personas con datos sintéticos y resultados agregados.
- Changelog y créditos con el aporte específico y enlace verificable.

Medir replicaciones documentadas, contribuciones útiles, correcciones aceptadas y colaboraciones sostenidas. Stars y visitas pueden ser indicadores secundarios, nunca garantía de impacto educativo.
