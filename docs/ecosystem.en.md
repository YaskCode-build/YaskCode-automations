# References, collaboration and visibility

[Español](ecosystem.md)

Help people learn with YaskCode, reuse its automations and collaborate through useful examples, verifiable results and meaningful community contributions. Referencing a project implies no partnership, affiliation or endorsement.

## Four complementary references

| Repository | Contribution | Use in YaskCode | Collaboration opportunity |
| --- | --- | --- | --- |
| [googleworkspace/apps-script-samples](https://github.com/googleworkspace/apps-script-samples) | Official service examples, solutions, triggers and .gs validation | Cross-check API usage and build exercises with original explanations | Reproducible fix or documentation improvement under its rules |
| [labnol/code](https://github.com/labnol/code) | Practical projects/snippets by Amit Agarwal / Digital Inspiration | Study example clarity and educational applications | Verified bug report or useful adaptation through an accepted channel |
| [labnol/apps-script-starter](https://github.com/labnol/apps-script-starter) | Vite, Jest, ESLint, Prettier and clasp environment | Tooling reference; initial V4 does not require these packages | Specific documentation or testing example within project scope |
| [hubspotdev/crm-object-sync](https://github.com/hubspotdev/crm-object-sync) | OAuth, PostgreSQL, Prisma and email-based synchronization demo | Compare persistence and authentication with Apps Script | Verified test case or documentation improvement |

The HubSpot demo uses a server and database. It is not a V4 dependency or an equivalent server-free deployment. These repositories were studied as references; their code has not been incorporated. Before reusing code, review the exact file/version license, retain notices and document adaptations. Sharing a platform does not itself grant reuse permission.

## GitHub mentions

| Mechanism | Expected effect |
| --- | --- |
| Repository link in README | Navigable reference, not guaranteed notification to authors |
| @username in issue, PR or Discussion | May notify a person with access, subject to GitHub conditions |
| @organization | Does not notify every member; teams have separate mechanisms and permissions |
| Mention in commit message | GitHub announced removal of these notifications in December 2025 |
| Star, fork or follow | Helps saving, reusing or following; no guaranteed reach or response |
| External PR | A real reviewable contribution under the receiving project's rules |

In a private repository, a mention does not grant access. Do not use a private PR mention as an introduction mechanism for external people.

## Proposed networking path

1. Complete a bilingual release with instructions, limitations and honest evidence.
2. Publish only after review and maintainer confirmation.
3. Read each external project's CONTRIBUTING, licenses and accepted channels.
4. Choose a small useful contribution: documentation, a verified reproduction or a test; check that it remains relevant.
5. Prepare a PR or useful discussion in an appropriate category, if available and open to project showcases. Use concise English and offer Spanish documentation as an additional resource.
6. Link the YaskCode case only where it provides relevant usage context, rather than as the entire contribution.
7. Share outcomes through the YaskCode campus, newsletter and social channels. Distinguish proposed, accepted and pending contributions; do not imply endorsement.

No messages, mentions, issues or PRs have been sent to these four projects. External actions require a concrete instruction and must follow the recipient project's rules.

## Multiplying the contribution

- Reciprocal Spanish/English guides covering the same technical version.
- A shared theory, comparison, practice, application and results template.
- Student exercises producing useful documentation or tests.
- Replications by others using synthetic data and aggregate results.
- Changelog and credits linking to the specific verified contribution.

Measure documented replications, useful contributions, accepted fixes and sustained collaboration. Stars and visits are secondary indicators, not proof of educational impact.
